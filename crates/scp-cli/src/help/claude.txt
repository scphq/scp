swarm claude [--name N | --as N] [--root] [--under ADDR] [--] [claude args...]   start Claude Code with the scp channel loaded, so peer messages wake it
swarm claude --bg [--name N] [--root] [--under ADDR] [--] [claude args...]   start it in the background (claude --bg) with an scp mount that claims N and
                                                 a grant, so it links under you; messages wake it through its inbox. Prints its short id and address
  --under ADDR links through the session claim to a local or cross-machine parent, without a grant; conflicts with --root.
  Run from an agent's shell, it links under that agent by itself, as under env $(swarm spawn-env --name N); a grant minted for
  it in $SCP_GRANT applies instead (your own spent grant is replaced), a resumed session keeps its place, --root starts it as a root
swarm claude attach <id|name> [--name N]    claude attach, renaming its endpoint to N first
  --resume <id> of a live background session attaches to it: it is already woken through claude-inbox
swarm claude ls [--all] [--json]          the background sessions (--all: stopped ones too), orchestrators first, with their SCP role
                                                 (orchestrator: a root or one with workers; worker; unknown: no endpoint), endpoint, policy
                                                 (kept: why, or due: stop or remove) and cwd
swarm claude prune [--dry-run] [--stop-only] [--older-than <dur>]   stop the idle workers swarm claude --bg started
                                                 now and remove them from claude agents, and the stopped ones whose endpoint is
                                                 gone: never a root, the caller's own session, one with live
                                                 workers or subagents, or one claude attach holds, that is not exactly
                                                 idle or that still runs a Bash tool command (kept: running a background
                                                 command), though a session busy only polling its inbox in a loop counts as idle,
                                                 and never claude rm --discard-unpushed or --force-remove-worktree. --older-than
                                                 (30m, 2h, 1d) replaces the thresholds; --stop-only removes nothing. Needs the broker
swarm claude prune --unhibernate-unrecorded [--dry-run]   clear the claude-bg hibernation of the endpoints of the
                                                 sessions swarm claude --bg did not start; stops, removes and respawns nothing
  The broker does the same on its own, for the workers swarm claude --bg started: idle without work one stops after
  $SCP_CLAUDE_BG_IDLE_AFTER_S (config.json claude_bg.idle_after_s), else the shared $SCP_IDLE_AFTER_S (lifecycle.idle_after_s;
  600 s, Infinity never), a done (or handed back) one after
  $SCP_CLAUDE_BG_STOP_AFTER_S (120 s) when sooner, and it leaves claude agents as it stops: $SCP_CLAUDE_BG_REMOVE is
  on_stop (the default; 1 and true mean it too), historic (removed only once its endpoint is historic) or 0 (the broker never removes);
  config.json claude_bg {stop_after_s, remove} sets those. $SCP_HISTORIC_AFTER_S (historic_after_s) sets
  when an agent turns historic.
  A stopped or removed worker keeps its endpoint and mail: a message that arrives after the stop respawns it (unread mail
  it already had does not), or resumes it in its directory after a removal
